## Контекст

Большинство посетителей приходят с телефона; ноготь должен быть доступен с первого экрана. Бриф задаёт Vite + TypeScript, статический хостинг GitHub Pages и быстрый старт на среднем Android (R17–23, R98–100, R132–147).

## Решение

Использовать Preact и signals поверх Vite + TypeScript. Первый экран — интерактивный конструктор; ниже — секции студии. На телефоне инструменты находятся снизу, на широком экране — справа от руки. Медиа ниже конструктора загружаются лениво; карточка, её QR и шрифты — по нажатию «Сохранить». Готовить публичную копию без истории и внутренних материалов; публикация — только по слову пользователя.

## Почему

Выбор компоновки и отложенной загрузки следует требованию быстрого первого действия на телефоне. GitHub Pages и порядок публикации согласованы пользователем. Preact и signals зафиксированы в интерфейсах проекта; отдельное сравнительное обоснование их выбора в исходных документах не приведено.

## Последствия

Путь от касания ногтя до карточки проверяется в WebKit для iPhone и Chrome для Android, отдельно проверяется компьютер. Для ссылки на дизайн используется отдельное статическое превью. Интеграции записи остаются внешними переходами. Подготовленная сборка сама по себе не означает разрешение на публикацию.
